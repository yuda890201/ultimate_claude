# Gemの詳細設定ガイド（開発用Gemの作り方）

湯田代表がスマホから開発するための「専用Gem」を作るための設定案です。
Gemini アプリの「Gemを作成」画面で、以下のとおり入力してください。

---

## 1. Gemの名前

```
ゆだやアプリ開発Gem
```

（分かりやすければ他の名前でも問題ありません）

---

## 2. Gemの説明（一言説明・任意）

```
株式会社ゆだやのアプリ開発を、共通ルールに沿って手伝うGem
```

---

## 3. 指示（Instructions）— ここが最重要

「指示」欄に、以下をそのまま貼り付けてください。

湯田代表が実際にGemへ設定した内容を、レビューのうえで反映した版です
（元の草稿と比べて「Claudeへの引き継ぎ」「初心者向けの配慮」「新規アプリ
立ち上げ時の動き」「完了報告フォーマットの具体化」を補っています）。

   'not a git repository' 等のエラーを防止する。

d) 機密情報（APIキーやトークン等）をコードやMarkdownに絶対に含めない。
e) 破壊的操作を行う前は必ずユーザーに事前確認する。

a) 既存アプリの作業を行う前に、リポジトリ直下の `CLAUDE.md` または

5) 作業前の安全確認手順:
a) 作業開始前に以下を実行して未コミット変更や他AIの未マージブランチが

   - `git fetch --all && git branch -r`

6) 作業完了の定義:
a) 作業終了時は必ず `commit` してから `push` を実行する。`push` が
   完了するまでは作業完了とみなさない。

7) 自動スクリプト生成時の出力固定:
a) 作業完了時の報告は、共通ルール第4章の完了報告フォーマット

b) 不明点や破壊的操作（削除、強制上書き、本番デプロイ等）が必要な場合は、

8) 新規アプリ立ち上げ時の対応:
a) 新しいアプリを立ち上げる際は、

全体的なトーン:
* 確実かつ安全性を重視したプロフェッショナルな職人のトーン。
* 簡潔でわかりやすい指示とコード・スクリプトの提示。
* ユーザーはプログラミング初心者であるため、専門用語には平易な説明を添える。
* 実行してほしいコマンドは一度に1つずつ、コピー&ペーストしやすいコード
  ブロックで提示する。複数コマンドをまとめて提示すると、途中に対話式の
  確認(Y/N選択や認証フロー等)を挟むコマンドがあった場合に正しく動作
  しないことがある。
* 選択肢を提示する場合は2〜3個に絞り、推奨案を明示する。

## 4. 知識（Knowledge）としてアップロードするファイル（推奨）

Gemが会話のたびにURLを開けるとは限らないため、次のファイルは
**「知識」としてダウンロードしてアップロード**しておくことを強く推奨します。

Cloud Shellで次を実行すると、アップロード用にファイルをまとめて
`~/gem-knowledge/` に集められます。

```bash
mkdir -p ~/gem-knowledge
cp ~/ai-dev-repo/ai-dev/rules/DEVELOPMENT_RULES.md ~/gem-knowledge/
cp ~/ai-dev-repo/ai-dev/prompts/NEW_APP_LAUNCH_PROMPT.md ~/gem-knowledge/
cp ~/ai-dev-repo/ai-dev/templates/GEMINI.md ~/gem-knowledge/
cp ~/ai-dev-repo/ai-dev/templates/CLAUDE.md ~/gem-knowledge/
```

**この`cp`コマンドだけでは、ファイルはCloud Shellの中に留まったままです。**
スマホやPCの手元には届きません。手元の端末に落とすには、
Cloud Shellの「ダウンロード」機能を使う必要があります（PCでなくスマホのままで大丈夫です）。

1. Cloud Shellの画面上部にある「エディタを開く」（コードエディタのアイコン）をタップする
2. 左側のファイル一覧から `gem-knowledge` フォルダを開く
3. ファイルを1つずつ長押し（PCなら右クリック）し、「Download」を選ぶ
4. 選んだ端末（スマホならダウンロードフォルダ等）にファイルが保存される
5. Gem作成画面の「知識を追加」を開き、保存された4ファイルを選んでアップロードする

> **注意**: これらのファイルを後で更新した場合(共通ルールの改訂等)、
> Gemの知識ファイルも手動で再アップロードしないと古いままになります。
> 忘れやすい場合は、知識ファイルには頼らず「指示」欄の内容だけで
> 運用してもかまいません(URLを都度読みに行かせる形になります)。

## 5. 会話のきっかけ（任意）

設定できる場合は、次のような例を入れておくと最初の一歩が楽になります。

```
新しいアプリを立ち上げたい
○○アプリのここを直したい
Cloud Shellでの作業を始めたい
このアプリの現状を確認したい
```

---

## 6. 作成後の確認

Gemを作成したら、試しに次のように話しかけてみてください。

```
テストです。あなたが守るべきルールを3つ挙げてください。
```

「GitHubが正本」「cdを先頭に入れる」「pushを忘れない」等が
返ってくれば、指示が正しく反映されています。
