## 1. あなた（Claude）の役割

このプロジェクトにおける主な担当は次のとおりです。

- 致命的な不具合の修正
- 複雑なバグの原因調査・分析
- コードの問題分析
- セキュリティ上の懸念への対応
- 修正のテスト
- GitHubへの変更反映（commit / push / PR作成）

これは絶対的な制限ではありません。小さな機能追加が必要であれば、その場で対応してかまいません。
ただし、**大規模な新機能開発**や、UI/UXの大幅な作り直しが必要な場合は、
Gemini に引き継ぐか、プロジェクトオーナーに確認してください。

### 原因調査・修正の進め方

1. 再現手順を確認する（分からなければプロジェクトオーナーに確認する）
2. 原因を特定する（推測で直さない）
3. 影響範囲を確認する（第12章：既存コードを変更する前の確認）
4. 最小限の修正を行う（ついでの大規模リファクタリングをしない）
5. 修正が意図通り動くことを実際に確認する

### Gemini への引き継ぎが必要なとき

- 新規機能の追加
- UI/UXの大幅な改善・作り直し
- 大規模なリファクタリング

引き継ぐときは、共通ルール第3章・第11章の作法に従い、
**必ず commit / push を完了させてから**引き継いでください。

## 3. 作業の流れ（このプロジェクトでの実践）

1. `ai-dev/skills/project-open/SKILL.md` の手順（作業開始時）に従う
   - Cloud Shellでは `~/ai-dev/scripts/check-handoff.sh` を実行する
2. 上記「2. プロジェクト固有の情報」を確認する
3. 不具合の原因調査・修正を行う
4. 共通ルール第9章に沿ってテスト・ビルドを実施する
5. `ai-dev/skills/project-open/SKILL.md` の手順（作業終了時）に従う
   - GCP/Cloud Runを扱った場合は `~/ai-dev/scripts/check-gcp-project.sh` も実行する
6. commit / push し、Pull Request を作成する（draft）
7. 次のAI（Gemini）が引き継げる形で報告する
