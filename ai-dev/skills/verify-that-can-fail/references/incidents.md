# 実例 — 通っていたのに何も守っていなかった検証

あるサービスを MCP 化した2日間で実際に起きたもの。どれも**検証は緑だった。**

> このファイルは公開リポジトリに置いてある。学びは失敗の**型**にあって
> どのサービスかには無いので、対象を特定できる記述は置かない。

各件「確かめたつもり」「実際に確かめていたこと」「直し方」を書く。

---

## 1. 421 を「認証成功」として報告した

- **確かめたつもり**: リモートMCPエンドポイントの認証が通ること
- **実際**: `if ($status -ne 401) { Ok }` と書いていた。
  `421 Misdirected Request` も合格になった。**しかも 421 のときは
  サーバは一切動いていない**（MCP層に到達する前に弾かれていた）
- **直し方**: 本番のクライアントと同じ `initialize` を投げ、
  **200 と `mcp-session-id` ヘッダの両方**を要求する
- **型**: 否定形で合格を決めた

## 2. 鍵が「パースできた」で ok を返した

- **確かめたつもり**: Web Push の VAPID 鍵が有効であること
- **実際**: ライブラリの読み込み関数を呼んで例外が出ないことだけを見て
  いた。診断は ok を返し続け、**実際の送信は ASN.1 のエラーで失敗した**
  （PEM を渡していたが、その関数は PEM を解釈できなかった）
- **直し方**: 診断の中で**実際に署名する**。署名できなければ ng
- **型**: 「存在する/パースできる」で止めた

## 3. 古いコードをデプロイして「OK」と表示した

- **確かめたつもり**: 最新のコードがデプロイされたこと
- **実際**: デプロイスクリプトが最初に `git pull` していたが、
  作業ツリーが汚れていて失敗していた。**PowerShell では
  `$ErrorActionPreference="Stop"` がネイティブコマンドに効かない**ので
  そのまま続行し、古いコードをデプロイして成功と表示した
- **直し方**: `$LASTEXITCODE` を見る。`HEAD` が `origin/<branch>` と
  一致することを確認する。さらに**デプロイ後、稼働中のサービス自身に
  「どのコミットで動いているか」を聞く**（確認の主体を移す）
- **型**: 手順の自己申告を根拠にした

## 4. 公開しているツールの一覧表が古くなった

- **確かめたつもり**: 手順書の表が実装と一致していること（誰も確かめて
  いなかった）
- **実際**: 実装は16ツール、表は12行、説明文は「15ツール」。
  表は「何が公開されているか」を人間が確認する唯一の場所なので、
  **公開しているつもりのないツールに気づけない**状態だった
- **直し方**: 表をパースして実装と突き合わせるテストを書く。
  ツールを1つ増やすと落ちる（実際に落ちて機能した）
- **型**: 人間が読む資料を、検証の対象に入れていなかった

## 5. 別オリジンの iframe の `contentDocument` を見ていた

- **確かめたつもり**: 認証情報を入力する画面が他サイトの枠に入れられない
  こと（クリックジャッキング対策）
- **実際**: 枠の中の `contentDocument` が `null` であることを確認して
  いた。**別オリジンの枠は、対策ヘッダの有無に関係なく `null` になる。**
  ヘッダを外してもテストは通った
- **直し方**: ブラウザが出す拒否のメッセージを見る
  （`Refused to frame ... frame-ancestors`）。ヘッダを外すと、代わりに
  枠の中のページが読み込まれた証拠が出るので、両方を区別できる
- **型**: 対象そのものを見ずに周辺を見た
- **補足**: 手順2（わざと壊す）を踏んだことで、**その場で捨てて
  作り直せた。** 踏まなければそのまま入っていた

## 6. スキップされたテストを「通った」と読んだ

- **確かめたつもり**: 全テストが通っていること
- **実際**: `OK (skipped=87)`。依存パッケージが入っていない環境だった
  ため、**本番で動くトランスポート（ASGI）のテストがまるごとスキップ
  されていた。** 2日間、本番の経路は一度も検証されていなかった
- **直し方**: 依存を入れて走らせる。スキップ件数を毎回読む。
  入れた結果スキップは6件になり、実行されるテストが 409→435 件になった
- **型**: 環境に依存する既定値で「通った」と見なした

## 7. ローカルでは通り、本番だけが落ちた

- **確かめたつもり**: エンドポイントが動作すること
- **実際**: MCP SDK は `streamable_http_app()` の `host` 引数の既定が
  `"127.0.0.1"` で、**その場合だけ** DNS リバインディング対策を自動で
  有効にする。localhost 宛ては通り、**公開ホスト名でだけ 421 になった**。
  応答本文は `Invalid Host header` の一行で、直し方は書かれていない
- **直し方**: 検査を自前の層に移し、拒否された値と直すべき環境変数を
  返すようにした。本番と同じホスト名で検証する
- **型**: ローカルで通ることを本番の証拠にした

## 8. 「設定されている」ことだけを確認した（3件）

- **シークレット**: 登録されていることは確認できたが、中身は改行1文字
  だった。`gcloud run services describe` は**参照しか見せない**ため、
  数時間気づかなかった → 実際に API を叩いて有効性を見る
- **状態の保存先**: 設定は正しく、保存も成功して見えた。インスタンスが
  止まると消える設定だったため、承認URLを開いた時点で初めて失敗した
  → 実際に書いて読んで消す検証を追加
- **貼り付けたトークン**: 2文字しか入っていなかった（貼り付け操作の
  問題）。登録直後に長さを出していれば即分かった
- **型**: どれも「参照・存在・見た目」を見て「実際に効くか」を見ていない

## 9. 自分のログに出ないことを「起きていない」と断定した

- **断定**: 「クライアントは認可サーバのメタデータを取りに行っていない」
- **実際**: そのときは外部の認可サーバを指していたので、**その取得は
  こちらのログには現れない。** 別の証跡から、実際には取得されていた
  ことが分かった
- **直し方**: 「ログに無い」は「起きていない」ではなく「観測できて
  いない」と書く。観測手段を用意してから断定する
- **型**: 観測範囲の外を、存在しないものとして扱った

## 10. 修正そのものに新しい穴を空けた（3件）

- リダイレクトURIの判定を文字列の先頭一致から `urlsplit` に直したが、
  `urlsplit` 自体が壊れた入力で `ValueError` を投げることを見ていな
  かった（500になる）。**テストを書いたときに初めて踏んだ**
- セキュリティヘッダ（CSP）を一律に課したら、承認画面のプレビューが
  無装飾になった。**実ブラウザで表示して目で見て気づいた**
- 新しいテストが環境変数を戻さず、**後から走るテストが実行順で落ちる**
  状態を作った
- **型**: 修正は検証の対象外だと思っていた。修正にも手順1〜4を適用する

---

## 数え方

- 「落ちない確認を確認として報告した」: 1, 2, 3, 4, 5
- 「設定は正しく見えるのに動かない」: 2, 3, 7, 8（3件）
- 「観測範囲の外を存在しないものとして扱った」: 9
- 「修正自体を検証しなかった」: 10

手順2〜3（わざと壊して落ちるところを見る）を踏んでいれば、
1・2・4・5 はその場で気づけた。3・6・7・8 は「実際に効くか」を見る
規則で防げた。
