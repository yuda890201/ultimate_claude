# Gemini アプリの Connected Apps に MCPサーバを繋ぐ

実機で確定させた内容。公式ドキュメントに書かれていない、または
到達できなかったため、試行で確かめたものである。

## 結論: MCPサーバ自身が認可サーバである必要がある

最初は「外部のIdPを認可サーバとして広告し、こちらはリソースサーバに
徹する」方針で作った。認可サーバを安全側に実装するのは難しいので、
**自作を避ける**という判断だった。

しかし Gemini アプリは接続しなかった。表示されたのは次のメッセージで、
原因は書かれていない。

```
この MCP サーバーはまだサポートされていません。
Gemini では、サーバー接続に標準の OAuth が必要です。
```

外部の認可サーバを指している間は、何度やっても進まなかった。
**MCPサーバ自身を認可サーバにしたら繋がった。**

当初は「地域や言語による制限では?」と疑ったが、それは外れだった。
外部の認可サーバを受け付けないことが原因である。

## 実機で通った要求の並び

```
HEAD /mcp                                       405
GET  /mcp                                       401 + WWW-Authenticate に resource_metadata
GET  /.well-known/oauth-protected-resource/mcp  200   (RFC 9728)
GET  /.well-known/oauth-authorization-server    200   (RFC 8414) ← 自分自身を指す
POST /oauth/register                            動的クライアント登録が成立 (RFC 7591)
GET  /oauth/authorize -> POST /oauth/decide     利用者が許可
POST /oauth/token                               トークン発行
```

## 実装上の要点

- **動的クライアント登録（RFC 7591）に対応する。** 対応しないと、
  利用者にクライアントIDとシークレットを手入力させることになる。
  登録画面にはそれを入れる欄しか無く、認可URL・トークンURL・
  リダイレクトURIの欄は無い
- **リダイレクトURIは Gemini が生成する。** 登録画面からコピーできるが、
  動的登録に対応していれば使わずに済む
- **PKCE は S256 で通る。** `plain` はメタデータに載せない
  （載せるとクライアントが選べてしまう）
- **トークンエンドポイントはフォーム形式**（RFC 6749 §4.1.3）。
  JSON しか受けないとトークン交換が成立しない。動的登録のほうは JSON
  なので、**両方を受けられるようにしておく**
- 認可コードの寿命を短くしすぎると、クライアント側の処理が間に挟まって
  `Session token is expired` で終わる。60秒では足りなかった。守るべきは
  「1回限り」であって短さではない（RFC 6749 は最大10分を推奨）
- サービスの表示名は、保護リソースメタデータの `resource_name` から
  取られる

## 自作した認可サーバで気をつけること

自作を避ける判断が覆ったので、安全側に寄せる責任がこちらに来る。
**書いた直後に見直すのが最も効く。** 実際に6件見つかった。

そのうち設計に関わるものを2つだけ挙げる。

### クライアントの「自称」を身元として表示しない

動的登録は開放する必要がある（しないと手入力に戻る）。つまり**誰でも
好きな `client_name` で登録できる。** 有名なアプリの名前を名乗って
登録し、自分のリダイレクトURIを指した認可URLを利用者に踏ませられる。

偽れないのは「認可コードがどこへ送られるか」だけなので、
**送信先のホストを最も大きく表示する。** 自称の名前は「確認されて
いません」と添えて小さく出す。一度も許可していないクライアントには
「初めてです。登録されたのは N 秒前です」を出す。攻撃はこの形で現れる。

### リダイレクトURIを文字列の先頭一致で判定しない

```python
# 悪い: http://127.0.0.1.evil.example/cb が通る
uri.startswith(("http://127.0.0.1", "http://localhost"))
```

ホスト名として取り出して等値で見る。なお `urlsplit` と `hostname` は
壊れた入力（`http://[::1].evil/`）で `ValueError` を投げるので捕まえる。
素通しすると登録エンドポイントが 500 を返し、登録が不正だったことが
呼び出し側に伝わらない。
